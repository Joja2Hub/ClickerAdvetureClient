# Аналитика и рекомендации квестов

## Назначение

Аналитический контур является дополнительным слоем над существующим сценарием квестов. Ошибка записи события не должна мешать созданию, отправке, проверке или получению награды.

## События

События хранятся в `children/{childId}/questEvents/{eventId}`.

- `quest_created` — квест создан родителем в Web;
- `quest_viewed` — карточка впервые показана в текущей сессии доски Unity;
- `quest_submitted` — ребенок отправил квест на проверку;
- `quest_approved` — родитель одобрил выполнение;
- `quest_rejected` — родитель отклонил выполнение;
- `quest_claimed` — ребенок получил награду;
- `quest_cancelled` — родитель отменил квест;
- `reminder_sent` — зарезервировано для напоминаний;
- `location_check_in_success` и `location_check_in_failed` — зарезервированы для геолокационных квестов.

Web пишет события родительских действий через `src/services/analyticsService.ts`. Unity использует `Assets/Scripts/Services/AnalyticsEventService.cs` и REST API Firestore. Unity-сервис перехватывает ошибки и только выводит предупреждение.

`quest_viewed` защищен от повторов через `viewedQuestIdsThisScreenSession` в `TownScreen`.

## Агрегаты

- Дневные показатели: `children/{childId}/analyticsDaily/{yyyy-MM-dd}`.
- Показатели по категориям: `children/{childId}/analyticsByCategory/{category}`.
- Рекомендации: `children/{childId}/recommendations/{category}`.

На этапе MVP родитель может запустить полный пересчет на странице аналитики. `rebuildAnalyticsForChild` читает журнал событий, группирует данные по датам и категориям и перезаписывает агрегаты. Повторный запуск на одном журнале дает тот же результат.

В Functions добавлены:

- `onQuestEventCreated` — пересчитывает аналитику после появления события;
- `rebuildChildAnalytics` — callable-функция полного пересчета;
- `generateQuestRecommendations` — повторная генерация рекомендаций.

## Экспертная система

Исходный score равен `50`. Результаты правил прибавляются к нему, итог ограничивается диапазоном `0..100`.

- `70..100` — `recommended`;
- `40..69` — `neutral`;
- `0..39` — `not_recommended`.

Правила версии `expert-v1`:

1. Успешная категория: `completionRate >= 0.75` и `rejectionRate <= 0.15`, `+25`.
2. Быстрое выполнение: среднее время не более 24 часов, `+15`.
3. Частые отклонения: `rejectionRate >= 0.35`, `-30`.
4. Низкая конверсия просмотра: минимум 3 просмотра и `viewToSubmitRate < 0.4`, `-20`.
5. Пять и более активных квестов за день, `-25`.
6. Усталость от категории: 5 назначений за 7 дней и успешность ниже 60%, `-20`.
7. Меньше трех назначений: совет начать с легкого задания.
8. Эффективная награда: успешность не ниже 70% при среднем золоте не более 50, `+10`.

Движок возвращает `score`, `label`, `reasons`, `risks`, `suggestedActions`, рекомендуемую сложность и награды.

## Интерфейс родителя

Страница аналитики показывает метрики, частые категории, отклонения, потребность в напоминаниях, таблицу категорий и рекомендации.

На форме создания квеста рекомендация загружается при выборе категории. Родитель может применить предложенную сложность и награды. Квест сохраняет `recommendationScore` и `recommended`, поэтому Unity показывает неброскую отметку «Совет дня».

## Безопасность

- Родитель читает события и агрегаты детей своей семьи.
- Родитель создает события своих действий.
- Ребенок создает только события со своим `childId`, ролью `child` и источником `unity`.
- События нельзя изменять и удалять.
- Ребенок не изменяет агрегаты и рекомендации.

## Что перенести в Cloud Functions перед production

1. Запретить клиентскую запись агрегатов и рекомендаций.
2. Использовать только триггер и callable-функции.
3. Перенести одобрение, отклонение и начисление награды в Functions.
4. Добавить идемпотентность событий для повторных сетевых запросов.
5. Для больших журналов заменить полный пересчет на инкрементальные агрегаты.
6. Добавить срок хранения или архивирование старых событий.
