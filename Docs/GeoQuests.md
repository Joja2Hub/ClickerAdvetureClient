# Геоквесты

Добавлена независимая от Unity и Firebase логика одного геоквеста:
`GeoQuestDefinition`, `GeoDistance`, `GeoQuestTracker` в пространстве имён
`ClickerAdventure`, как и остальные системы актуального клиента.

Родительский сценарий: школа, радиус 100 метров, пять посещений за
фиксированный недельный интервал. Начало включено, конец исключён.
Повторные отметки в один календарный день не увеличивают прогресс.
День определяется фиксированным смещением задания (по умолчанию UTC+3),
а не часовым поясом телефона. Это пока один интервал, без автоповтора недели.

`RegisterVisit` принимает координаты, точность в метрах и время наблюдения.
Посещение засчитывается, если вся окружность погрешности помещается в радиус
точки. Поэтому при плохом GPS рядом с границей посещение может не засчитаться.
После достижения цели счётчик больше не увеличивается. Трекер копирует условия
при создании; изменение исходной модели не меняет активный подсчёт.

Проверка: `powershell -ExecutionPolicy Bypass -File Tests/GeoQuests/Run.ps1`
(требуется .NET SDK 9; временные файлы создаются в игнорируемой `Temp/GeoQuestChecks`).

## Проверка в Unity Editor

Откройте `RPG Quest → Geo Quests → Test Visit Tracking`. Play Mode не требуется.

1. Оставьте исходные условия: радиус 100 метров, пять посещений за семь дней.
2. Нажмите «Создать / сбросить тестовый квест».
3. Нажмите «Отметить посещение»: прогресс станет 1.
4. Повторите отметку в день 0: прогресс останется 1.
5. Последовательно выберите дни 1, 2, 3, 4 и отметьте посещения: цель достигнута.
6. Сбросьте квест и измените широту ребёнка на 56: точка окажется вне радиуса.
7. Проверьте погрешность 150 метров и дни -1 и 7: отметки не засчитываются.

Неделя в этом окне — семь дней с текущей даты, начало в полночь заданного
смещения UTC. Изменение условий применяется кнопкой сброса. Окно не записывает
данные в Firebase и не выдаёт награды. Начиная с этапа 3 окно сохраняет посещения
локально и восстанавливает их после перезагрузки скриптов, пока определение
тестового квеста сохранено в состоянии окна Unity.

На первом этапе модуль не подключён к сценам: нет GPS, интерфейса родителя,
хранилища и выдачи наград. Прогресс живёт только в памяти экземпляра трекера.
Время и координаты передаются вызывающим кодом; это ещё не доверенное
подтверждение посещения. При подключении GPS нужно проверять свежесть замера,
а при подключении Firebase — права семьи и повторную отправку отметок.

## Этап 2 — источник координат

`GeoLocationProvider` добавляется компонентом на активный объект сцены.
Он не запускается автоматически: вызывающий код запрашивает координаты
при нажатии кнопки отметки. Пример подключения к существующему трекеру:

```csharp
provider.RequestLocation(
    reading =>
    {
        GeoVisitResult result = tracker.RegisterVisit(reading.Latitude,
            reading.Longitude, reading.AccuracyMeters, reading.ObservedAt);
        // Отобразить result и tracker.VisitCount в интерфейсе.
    },
    error => { /* Отобразить ошибку и предложить повторить запрос. */ });
```

В Unity Editor используются поля Editor Latitude / Longitude / Accuracy Meters
в Inspector. Они исключены из сборки телефона. Для проверки можно менять точку
и точность между запросами, включая выход за радиус и повторную отметку за день.

На Android/iOS используется `Input.location`: ожидание ограничено 20 секундами,
замеры старше 30 секунд или из будущего не принимаются. После получения точки,
ошибки, отключения компонента или ухода в фон служба останавливается.
Чужая активная GPS-сессия возвращает Busy. На других платформах — Unavailable.
Отказ в доступе или выключенное местоположение обрабатываются без записи посещения.
После возврата в приложение запрос нужно повторить.

Unity обрабатывает системный запрос доступа к геолокации. Для iOS перед сборкой
нужно заполнить Location Usage Description в Player Settings; на Android
не следует отключать автоматический запрос разрешений настройкой
`unityplayer.SkipPermissionsDialog`. Поведение Location Service описано в
[документации Unity](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/LocationService.Start.html).

Проверки свежести и корректности замеров включены в консольный набор тестов.
Окно Editor и мобильные ветки дополнительно проверены компиляцией с DLL
установленной Unity 6000.3.11f1.
Получение GPS и системные разрешения нужно отдельно проверить на телефоне.

Компонент пока не добавлен в игровые сцены. Следующий этап — экран проверки
геоквеста, затем создание задания родителем и сохранение прогресса в Firebase.

## Этап 3 — локальное сохранение прогресса

`GeoQuestTracker.CreateSaveData()` создаёт независимый снимок посещений.
Конструктор `GeoQuestTracker(definition, progress)` восстанавливает его с
проверкой версии, срока и уникальности дней. Координаты наблюдений не сохраняются:
в снимке находятся времена засчитанных посещений и хеш условий задания.

`GeoQuestLocalStore` сохраняет снимки в JSON в
`Application.persistentDataPath/GeoQuests`. Имя файла — хеш пары ребёнок/задание:
идентификаторы не используются как части пути. В хеш условий входят точка,
радиус, число посещений, период, часовой пояс и ID задания. Изменение названия
не сбрасывает прогресс. При изменении условий или повреждении файла загрузка
завершается явной ошибкой; существующий файл не перезаписывается при чтении.

```csharp
var store = new GeoQuestLocalStore();
GeoQuestTracker tracker = store.Load(childId, definition);
// После успешного RegisterVisit:
store.Save(childId, tracker);
```

Сначала запись идёт во временный файл в том же каталоге, затем заменяет основной.
Ошибка сохранения передаётся вызывающему коду; при ней прогресс может остаться
только в памяти, поэтому интерфейс должен предложить повторить сохранение.
Локальный файл не является доверенным доказательством для выдачи наград.
Синхронизация и разрешение конфликтов между устройствами ещё не реализованы.

Тестовое окно использует отдельную папку `GeoQuestEditorPreview` и демонстрационный
ID ребёнка. Отметки сохраняются автоматически; есть кнопки повторного сохранения
и загрузки с диска. Для проверки отметьте день 0, загрузите прогресс и повторите
отметку: счётчик не должен вырасти. Кнопка создания/сброса намеренно сохраняет
нулевой прогресс. Закрытие окна не удаляет файл, но для его восстановления нужно
то же определение задания; сам список заданий пока не хранится этим модулем.

Консольные проверки охватывают запись/повторную запись JSON, восстановление,
разделение детей, повреждённый файл, изменённые условия и дубли дат. В тестах
Unity JsonUtility заменён сериализатором .NET; код трекера и хранилища настоящий.
Работу файловой системы и JSON на телефоне ещё нужно проверить в Unity-сборке.

## Этап 4 — единый сценарий отметки посещения

`GeoQuestCheckInService` связывает источник координат, трекер и хранилище.
Его нужно создать один раз для экрана и вызывать в главном потоке Unity:

```csharp
var checkIns = new GeoQuestCheckInService(locationProvider, new GeoQuestLocalStore());
// При нажатии кнопки, в асинхронном обработчике:
GeoCheckInResult result = await checkIns.CheckInAsync(childId, definition);
```

Сначала загружается текущий прогресс. Затем запрашиваются координаты и повторно
проверяется свежесть замера (по умолчанию 30 секунд). Засчитанное посещение
сохраняется до возврата результата Counted. Отклонённая или повторная отметка
не вызывает запись файла. Если цель уже достигнута, GPS не запускается.

Результат различает VisitChecked с конкретным GeoVisitResult, LocationFailed
с причиной GeoLocationError, InvalidReading и Busy. При Busy счётчик неизвестен:
интерфейс должен оставить текущий прогресс, а не использовать VisitCount.
Параллельный запрос к тому же экземпляру сервиса не запускает второй GPS-запрос.
Для нескольких экранов при интеграции следует использовать общий экземпляр.

Ошибки загрузки и сохранения передаются вызывающему коду как исключения.
При неудачной записи успешная отметка не возвращается; новая попытка загружает
прогресс с диска, поэтому несохранённая отметка не блокирует повторение в тот же
день. Интерфейсы IGeoLocationSource и IGeoQuestProgressStore позволяют проверять
это поведение без настоящего GPS и проблем на реальном диске.

Источник координат обязан завершать запрос успешным или ошибочным callback.
GeoLocationProvider уже ограничивает ожидание и отменяет запрос при отключении
компонента или уходе в фон. Сервис не отслеживает геопозицию постоянно.

Набор расширен до 82 проверок. Клиент и окно Editor компилируются с библиотеками
Unity 6000.3.11f1. Проверки сценария используют подставной источник координат
и хранилище; получение GPS на телефоне ещё не проверено. Кнопка игрового UI,
формат задания с родительского сайта и отправка отметок в Firebase остаются
следующими отдельными этапами.
