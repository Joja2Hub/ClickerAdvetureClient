# Геоквесты

Добавлена независимая от Unity и Firebase логика одного геоквеста:
`GeoQuestDefinition`, `GeoDistance`, `GeoQuestTracker` в пространстве имён
`ClickerAdventure`, как и остальные системы актуального клиента.

Родительский сценарий: школа, радиус 100 метров, пять посещений за
фиксированный недельный интервал. Начало включено, конец исключён.
Повторные отметки в один календарный день не увеличивают прогресс.
День определяется фиксированным смещением задания (по умолчанию UTC+3),
а не часовым поясом телефона. Это пока один интервал, без автоповтора недели.

`RegisterVisit` принимает координаты, точность в метрах и время наблюдения.
Посещение засчитывается, если вся окружность погрешности помещается в радиус
точки. Поэтому при плохом GPS рядом с границей посещение может не засчитаться.
После достижения цели счётчик больше не увеличивается. Трекер копирует условия
при создании; изменение исходной модели не меняет активный подсчёт.

Проверка: `powershell -ExecutionPolicy Bypass -File Tests/GeoQuests/Run.ps1`
(требуется .NET SDK 9; временные файлы создаются в игнорируемой `Temp/GeoQuestChecks`).

## Проверка в Unity Editor

Откройте `RPG Quest → Geo Quests → Test Visit Tracking`. Play Mode не требуется.

1. Оставьте исходные условия: радиус 100 метров, пять посещений за семь дней.
2. Нажмите «Создать / сбросить тестовый квест».
3. Нажмите «Отметить посещение»: прогресс станет 1.
4. Повторите отметку в день 0: прогресс останется 1.
5. Последовательно выберите дни 1, 2, 3, 4 и отметьте посещения: цель достигнута.
6. Сбросьте квест и измените широту ребёнка на 56: точка окажется вне радиуса.
7. Проверьте погрешность 150 метров и дни -1 и 7: отметки не засчитываются.

Неделя в этом окне — семь дней с текущей даты, начало в полночь заданного
смещения UTC. Изменение условий применяется кнопкой сброса. Окно не записывает
данные в Firebase и не выдаёт награды; перезагрузка скриптов сбрасывает прогресс.

На первом этапе модуль не подключён к сценам: нет GPS, интерфейса родителя,
хранилища и выдачи наград. Прогресс живёт только в памяти экземпляра трекера.
Время и координаты передаются вызывающим кодом; это ещё не доверенное
подтверждение посещения. При подключении GPS нужно проверять свежесть замера,
а при подключении Firebase — права семьи и повторную отправку отметок.

## Этап 2 — источник координат

`GeoLocationProvider` добавляется компонентом на активный объект сцены.
Он не запускается автоматически: вызывающий код запрашивает координаты
при нажатии кнопки отметки. Пример подключения к существующему трекеру:

```csharp
provider.RequestLocation(
    reading =>
    {
        GeoVisitResult result = tracker.RegisterVisit(reading.Latitude,
            reading.Longitude, reading.AccuracyMeters, reading.ObservedAt);
        // Отобразить result и tracker.VisitCount в интерфейсе.
    },
    error => { /* Отобразить ошибку и предложить повторить запрос. */ });
```

В Unity Editor используются поля Editor Latitude / Longitude / Accuracy Meters
в Inspector. Они исключены из сборки телефона. Для проверки можно менять точку
и точность между запросами, включая выход за радиус и повторную отметку за день.

На Android/iOS используется `Input.location`: ожидание ограничено 20 секундами,
замеры старше 30 секунд или из будущего не принимаются. После получения точки,
ошибки, отключения компонента или ухода в фон служба останавливается.
Чужая активная GPS-сессия возвращает Busy. На других платформах — Unavailable.
Отказ в доступе или выключенное местоположение обрабатываются без записи посещения.
После возврата в приложение запрос нужно повторить.

Unity обрабатывает системный запрос доступа к геолокации. Для iOS перед сборкой
нужно заполнить Location Usage Description в Player Settings; на Android
не следует отключать автоматический запрос разрешений настройкой
`unityplayer.SkipPermissionsDialog`. Поведение Location Service описано в
[документации Unity](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/LocationService.Start.html).

Проверки свежести и корректности замеров включены в консольный набор тестов.
Окно Editor и мобильные ветки дополнительно проверены компиляцией с DLL
установленной Unity 6000.3.11f1.
Получение GPS и системные разрешения нужно отдельно проверить на телефоне.

Компонент пока не добавлен в игровые сцены. Следующий этап — экран проверки
геоквеста, затем создание задания родителем и сохранение прогресса в Firebase.
