# Получение награды — 29 октября 2026

Онлайн-клиент получает награду только через `claimQuestReward`. В исходниках
серверной функции уже есть транзакция: проверка approved и rewardLedger,
отметка claimed и начисление XP/золота. Сервер в этом изменении не менялся
и не развёртывался.

Удалён клиентский обход: после ошибки облачной функции приложение больше
не пишет claimed напрямую в Firestore и не начисляет награду локально.
Это важно, если сервер успел выполнить транзакцию, но ответ потерялся.

После успешного подтверждения клиент загружает баланс. Если загрузка
не удалась, пользователь видит сообщение, что награда уже получена
на сервере, а баланс нужно обновить. Ошибка запроса награды показывает
сообщение о необходимости обновить задания и проверить баланс перед повтором.
В обоих случаях исходное исключение сохраняется как InnerException.

До запроса проверяется статус Approved. Локальное начисление осталось
в существующем демо-режиме без авторизации Firebase.

Сервис выделен из `Core/GameServices.cs` в
`Assets/Scripts/Rewards/CloudFunctionsService.cs`, пространство имён и
вызовы ServiceRegistry сохранены. Удалён метод
`FirebaseRestClient.ClaimQuestRewardDirectAsync`.

Проверка: `powershell -ExecutionPolicy Bypass -File Tests/Rewards/Run.ps1`
с .NET SDK 9. Тесты компилируют реальный сервис с подменами сетевого клиента
и хранилища: успех, потерянный ответ, сбой обновления баланса, недопустимые
статусы, null-задание и локальное начисление. Прошли 20 проверок и компиляция
кода клиента с библиотеками Unity 6000.3.11f1.

Живой Firebase в проверках не использовался. Для онлайн-режима должна быть
развёрнута и доступна серверная функция claimQuestReward; при её отсутствии
клиент теперь покажет ошибку вместо самостоятельного начисления.
